# Direct NASA/JPL data provenance — 14 November 2026

All runtime scientific raster/vector arrays have been rebuilt directly from authoritative archives. The successful run is [Rebuild authoritative NASA data](https://github.com/Dima000000/NASA-lunar-navigator/actions/runs/43625400632). The [retrieval audit](direct-source-audit.json) records original URLs, byte counts, download hashes and the hashes/bounds of extracted 20 m COG windows. No scientific runtime arrays from a third-party mirror remain in this release. An earlier prototype used an attributed mirror; its historical source-tree and archived reference metadata remain for traceability, not as runtime inputs. No application code from that mirror is used.

Sphere radius 1,737,400 m; planetocentric latitude, east-positive longitude. Polar stereographic x=2R tan((90°+lat)/2) sin(lon), y=2R tan((90°+lat)/2) cos(lon). Local grids use site-centred east/north stereographic coordinates. Heights in preparation files are metres; rendering heights are kilometres relative to the site centre. The 481² display grid has 33.33 m spacing, which adds no measurements beyond source sampling.

Selected-site horizon profiles use finite rays to 300 km, 0.5° azimuth sampling. Catalogue map/route atlases use 533 m cells and 5° azimuth sampling; narrow obstacles may be missed. Custom-point spatial atlases trace measured terrain to 300 km; finite azimuth/radial sampling can miss narrow obstacles. A 15° landing and 20° rover cutoff are scenario assumptions, not NASA safety requirements. Vehicle battery/panel/load/speed and the descent animation are hypothetical; geometric Earth visibility is not a guaranteed radio link.

Coordinate roles and citations are in catalog.json and each meta.json. Research points are not NASA-approved landing points. Publications supply comparison facts, not copied article images/text. Original interface: [NASAL PR #1](https://github.com/gleb31415/NASAL/pull/1), f0732335864ab7c93a63a95542f48bda4a3d43b6; CSS retained. Font: Inter, bundled SIL OFL.

## Review update — 15 November 2026

Scientific inputs are versioned release assets; `tools/science-inputs.json` pins their sizes/SHA256 and the immutable fallback commit. `bootstrap-data.py` verifies every restored array. The repository retains code, small metadata, profiles and research records rather than new binary-array revisions. `package-data.py` creates the release asset; the authoritative NASA rebuild publishes it before committing updated hashes/metadata. An initial release asset may be absent until the workflow is run; bootstrap then verifies the pinned historical snapshot instead. No archive is trusted just because it downloaded successfully.

`prepare-delivery.py` produces lossless gzip float32 site heights/horizon atlases, gzip masks, and separate lossless yearly ephemerides with an overlapping boundary sample. Browser regressions confirm the original 4326 Horizons comparisons after this delivery change. Optional Uint16 display-only heights are quantized to 0.1 m using float64 arithmetic and audited for at most 0.05 m rounding error; scientific computations retain original float32 values. Grayscale JPEG at quality 90 is used only for photographic brightness, never for encoded elevations or masks. A runtime manifest supplies sizes and hashes; the browser verifies loaded bytes and handles both raw gzip delivery and HTTP Content-Encoding decompression.

The first globe is a measured coarse preview: 512×256 global elevation and 512×512 polar elevation (~1187.5 m polar pixels), plus 1024×512 global colour. At first overview interaction it upgrades to the original full global/polar rasters and mesh; no invented heights fill the transition. Catalogue local meshes remain 481×481 with original measured inputs. The preview is for orientation, not for estimating local slopes or terrain horizons.

Custom-point spatial atlases now trace actual global/polar terrain to 300 km at 5° azimuth on 31×31 nodes. Their selected-pin profiles use 0.5° sampling. This replaces the earlier crop-limited spatial approximation; finite ray sampling and interpolation remain limitations. Route cells use maximum contained display-grid slope and reject blocked diagonal corners. Up to six non-dominated time/charge labels per group are retained, with waiting-energy-aware dominance; capped fronts and expansion limits still make the search approximate. Continuous Wh and ≤15 min light integration are retained.

Lighting and map pixels are computed off the main thread, with one active request and latest-time coalescing. This changes scheduling, not the underlying visibility formula; the browser regression found zero difference from the synchronous reference across the display grid.
